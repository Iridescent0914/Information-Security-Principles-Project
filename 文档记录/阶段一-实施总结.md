# 阶段一：环境检查与 UDP 基础通信实施总结

## 1. 阶段目标

阶段一的目标是确认当前最终拓扑具备后续安全隧道开发所需的基础条件，并验证 Kali 客户端与 VMware Ubuntu 服务端之间可以通过 UDP `2026` 进行双向通信。

本阶段只验证：

- Python 运行环境；
- `cryptography` 密码库；
- ECDH / AES-GCM / HKDF 基础能力；
- `/dev/net/tun`；
- `tcpdump`；
- `iptables`；
- UDP `2026` 监听；
- Kali → VMware 的 UDP 请求；
- VMware → Kali 的 UDP Echo 返回；
- `tcpdump` 抓包；
- `.pcap` 文件保存。

本阶段**不创建自定义 `tjvpn0`**，也**不配置 IP Forwarding、NAT 或默认路由切换**。

---

## 2. 当前最终实验拓扑

阶段一采用的实际拓扑如下：

```text
Kali 172.30.0.2
自定义 VPN Client
        │
        │ UDP 2026
        │ 经老师课程 OpenConnect VPN 承载
        ▼
VMware Ubuntu
课程 VPN 地址：172.29.255.229（本次会话）
自定义 VPN Server
        │
        ├─ OpenConnect 接口：tun0
        └─ 公网出口接口：ens33
                 │
                 ▼
            VMware NAT
                 │
                 ▼
              Internet
```

注意：

- Kali `172.30.0.2` 是后续自定义 VPN Client；
- VMware Ubuntu 是后续自定义 VPN Server 和公网 NAT 出口；
- VMware 上的 `tun0` 是老师 OpenConnect 创建的课程 VPN 接口；
- 后续我们自己的 TUN 接口统一命名为 `tjvpn0`，避免与 OpenConnect 的 `tun0` 冲突；
- 本次 OpenConnect 分配给 VMware 的地址是 `172.29.255.229`，课程 VPN 重连后该地址可能变化。

## 7. 编写 UDP Echo 服务端

在 VMware Ubuntu：

```bash
cd ~/secure_tunnel
```

创建：

```text
udp_echo_server.py
```

内容：

```python
import socket

HOST = "0.0.0.0"
PORT = 2026

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind((HOST, PORT))

print(f"UDP server listening on {HOST}:{PORT}")

while True:
    data, addr = sock.recvfrom(4096)
    print(f"Received {data!r} from {addr}")
    sock.sendto(b"echo:" + data, addr)
```

启动：

```bash
python3 udp_echo_server.py
```

正常输出：

```text
UDP server listening on 0.0.0.0:2026
```

## 9. 编写 UDP Echo 客户端

在 Kali：

```bash
cd ~/secure_tunnel
```

创建：

```text
udp_echo_client.py
```

内容：

```python
import socket

SERVER_IP = "172.29.255.229"
SERVER_PORT = 2026

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(3)

message = b"hello udp"

print(f"Sending {message!r} to {SERVER_IP}:{SERVER_PORT}")
sock.sendto(message, (SERVER_IP, SERVER_PORT))

data, addr = sock.recvfrom(4096)
print(f"Received {data!r} from {addr}")
```

说明：

```text
172.29.255.229
```

只是本次 OpenConnect 会话分配给 VMware 的课程 VPN 地址，后续正式 `client.py` 不应写死，应改为命令行参数 `<SERVER_VPN_IP>`。

## 13. 阶段一过程中遇到的问题

### 13.1 Kali pip3 无法运行

表现：

```text
TypeError: dataclass() got an unexpected keyword argument 'slots'
```

处理方式：

- 不升级系统 pip；
- 不修改 Kali 的旧 Python 环境；
- 直接使用系统已经安装的 `cryptography 3.3.1`；
- 实际功能测试确认 ECDH、AES-GCM、HKDF 均可正常使用。

### 13.2 VMware apt 被 unattended-upgrades 占用

表现：

```text
Could not get lock /var/lib/dpkg/lock-frontend
```

处理方式：

- 不删除 apt/dpkg 锁文件；
- 不强制终止系统包管理进程；
- 先检查已有 `cryptography`；
- 确认 VMware 已安装 `cryptography 3.4.8` 且功能完全满足要求，因此无需继续安装。

### 13.3 一次 UDP Echo 超时

Kali 曾出现：

```text
socket.timeout: timed out
```

同时 tcpdump 能看到：

```text
Kali → VMware
```

请求，但没有响应。

原因是当时 VMware 上的：

```text
udp_echo_server.py
```

没有保持运行。

重新启动：

```bash
python3 udp_echo_server.py
```

后双向 Echo 恢复正常。

该现象也验证了 tcpdump 对定位网络问题很有帮助：

```text
有请求、无响应
→ 优先检查服务端进程/监听状态
```
