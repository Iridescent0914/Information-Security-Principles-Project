# 阶段七：最终抓包、安全异常验证与证据整理实施总结

## 1. 阶段目标

阶段七的目标是在阶段一至阶段六功能已经完成的基础上，不再增加新的核心网络功能，而是完成最终验收需要的抓包、密文一致性验证、安全异常测试和环境清理。

本阶段主要完成：

- 从干净环境重新启动正式 Client / Server；
- 抓取完整正常握手；
- 确认正常握手严格为 6 个 UDP `2026` 报文；
- 保存 Client / Server 最终握手日志；
- 验证双方 Pre-Master、Transcript Hash、Session Key 一致；
- 从 `tjvpn0` 重新验证真实 IPv4 Packet；
- 对课程指定目标 `202.120.2.101` 进行单包 Ping；
- 在 Client 中输出指定 DATA 的完整调试信息；
- 输出 TJ Header、Sequence Number、IV、Plaintext、Ciphertext、Auth Tag、Payload、Full Packet；
- 在 VMware `tun0` 抓取对应的实际 UDP `2026` 报文；
- 从 pcap 中提取真实 UDP Payload；
- 对程序生成的 `full_packet` 与 pcap UDP Payload 做逐字节比较；
- 验证 Replay 拒绝；
- 验证 Ciphertext 篡改拒绝；
- 验证 Auth Tag 篡改拒绝；
- 故意构造错误 ClientFinished；
- 验证错误 Finished 不能进入 `ESTABLISHED`；
- 验证错误握手只有 5 个网络报文；
- 再次验证 CLOSE；
- 恢复正式代码；
- 清理 TUN、路由、NAT、FORWARD 和测试进程；
- 生成最终自动验收结果 `07_final_check.txt`。

# 16. Server 拒绝错误 ClientFinished

Server 正常完成前四条握手并得到与 Client 相同的：

```text
Pre-Master SHA256
Transcript SHA256
Session Key SHA256
```

收到错误 ClientFinished 后：

```text
[HANDSHAKE] Received ClientFinished

[FINISHED] Client Finished verification FAILED

ValueError:
Client Finished verification failed
```

Server 立即终止握手。

---

# 17. 错误 Finished 不能进入 ESTABLISHED

自动判定：

```text
[PASS] invalid ClientFinished rejected; session not established
```

检查逻辑同时要求：

```text
Server 日志存在：
Client Finished verification FAILED
```

并且不存在：

```text
[STATE] ESTABLISHED
```

因此可以确认：

```text
Finished 验证失败
→ 不允许建立会话
→ 不允许 DATA
```

---

# 19. Client 超时属于预期行为

错误 ClientFinished 发送后，Client 继续等待：

```text
ServerFinished
```

但 Server 已拒绝会话并退出。

因此 Client 最后出现：

```text
socket.timeout: timed out
```

这是负面测试的预期现象，不是网络故障。
